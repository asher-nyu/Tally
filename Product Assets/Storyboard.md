# Entire-screen screenshot plan

Capture three views for each fictional person. Each person owns one ongoing file that continues across months and years; the annual view changes the period, not the file. The interface itself tells each story. No marketing headline or hardware frame appears in the final image. Use the same person and file throughout each platform's sequence so the screenshots feel like a coherent daily routine.

Existing set: eight images use Release build 15. `Tally-iPhone-03.png` was recaptured from Release build 21 on September 29, 2026, with Ripple selected; its Product Screenshots and App Store copies are identical. The iPhone and iPad status bars are set to **9:41 AM on Monday, September 28, 2026**; every iPad image visibly shows “9:41 AM Mon Sep 28,” while the iPhone status bar displays “9:41.” Mobile batteries are full and not charging. October shows the updated This month button; the current September and 2026 views correctly hide it. All images preserve their native dimensions and original RGB pixels, with no cursor, scroll indicator, or iPad resize corner. The Mac menu bar, Dock, and other windows are hidden during capture. Temporary display and simulator status settings are restored afterward.

All Mac images capture the entire native desktop with Tally at its **normal default 860 × 680 pt window size**, centered horizontally and vertically. Hide the menu bar and Dock. Match opposing margins within native one-point window-position rounding; do not force all four margins to be identical. Never zoom, maximize, enter full-screen mode, or stretch the window or image. Preserve the native 3456 × 2234 desktop capture without cropping or stretching. iPhone images use the entire portrait display; iPad images use the entire landscape display. Capture UI as it actually appears: do not rebuild controls, move totals in an image editor, crop away inconvenient elements, or substitute text.
